# Сети:

## Модель OSI

Модель OSI (Open Systems Interconnection) — это концептуальная модель, разработанная для стандартизации функций сетевых систем без учета их внутренней структуры и технологии. Она делит сетевые функции на семь уровней:

![OSI](https://media.fs.com/images/community/wp-content/uploads/2017/11/seven-layers-of-OSI-model.png)

1. Физический уровень (Physical Layer) — передача необработанных битов по физическим средам.
2. Канальный уровень (Data Link Layer) — передача данных между узлами в одной сети, управление доступом к среде.
3. Сетевой уровень (Network Layer) — маршрутизация пакетов данных между различными сетями.
4. Транспортный уровень (Transport Layer) — надежная передача данных между конечными узлами.
5. Сессионный уровень (Session Layer) — управление сессиями между приложениями.
6. Представительский уровень (Presentation Layer) — преобразование данных для приложения, включая кодирование и шифрование.
Прикладной уровень (Application Layer) — интерфейс для пользовательских приложений.

## BGP (Border Gateway Protocol)

BGP — это протокол маршрутизации, используемый для обмена маршрутной информацией между автономными системами (AS) в Интернете.
Он является основным протоколом для маршрутизации между различными сетями.

Различные метрики для выбора маршрута

BGP использует несколько атрибутов для выбора маршрута, включая:

* AS Path — список автономных систем, через которые прошел маршрут.
* Next Hop — IP-адрес следующего узла, к которому следует отправить пакеты.
* Local Preference — предпочтение маршрута внутри автономной системы.
* Multi-Exit Discriminator (MED) — предпочтение маршрута для входа в автономную систему.
* Origin — указывает, как был получен маршрут (IGP, EGP, или инъекция).
  
## Автономная система

Автономная система (AS) — это группа IP-сетей и маршрутизаторов под управлением одного или нескольких операторов, 
которые имеют единый и четко определенный маршрутный протокол. Каждой автономной системе присваивается уникальный номер (ASN).

### Установка BGP-сессии – состояния сессии
BGP-сессия может находиться в нескольких состояниях:

1. Idle — начальное состояние, когда сессия не активна.
2. Connect — состояние, когда BGP пытается установить TCP-соединение.
3. Active — состояние, когда BGP пытается установить соединение, но не может.
4. OpenSent — состояние, когда BGP отправил сообщение Open, но не получил ответ.
5. OpenConfirm — состояние, когда BGP получил сообщение Open и ожидает подтверждения.
6. Established — состояние, когда сессия успешно установлена, и маршруты могут обмениваться.
Эти состояния помогают отслеживать процесс установки и поддержания BGP-сессии.

# DNS
DNS (Domain Name System) — это система доменных имен, которая переводит понятные человеку доменные имена (например, www.example.com) в IP-адреса (например, 192.0.2.1), которые используются для идентификации устройств в сети. 
DNS позволяет пользователям обращаться к ресурсам в интернете, не запоминая числовые адреса.

## Для чего DNS-сервер использует в работе TCP/53 помимо UDP/53?

DNS-серверы используют UDP (User Datagram Protocol) для большинства запросов, так как это более быстрый и менее ресурсоемкий протокол. 
Однако TCP (Transmission Control Protocol) используется в следующих случаях:

* Большие ответы: Если ответ на DNS-запрос превышает 512 байт (например, при передаче DNS-записей с большим количеством данных), используется TCP для передачи данных.
* Передача зон: При передаче зон (AXFR) между DNS-серверами используется TCP, так как это требует надежной передачи данных.
* Надежность: TCP обеспечивает надежность передачи данных, что важно для некоторых операций, таких как обновление зон или передача больших объемов информации.

## Типы записей (в первую очередь A, SOA, MX)

* A (Address Record): 
Запись типа A связывает доменное имя с его соответствующим IPv4-адресом. Например, запись A для www.example.com может указывать на IP-адрес 192.0.2.1.

* SOA (Start of Authority):
 Запись SOA содержит основную информацию о зоне DNS, включая имя основного сервера, адрес электронной почты администратора, номер версии зоны, время обновления и другие параметры.

* MX (Mail Exchange): 
Запись MX указывает на почтовый сервер, который отвечает за обработку электронной почты для домена. Она содержит приоритет и адрес почтового сервера.

Как посмотреть TTL DNS-записи (в том числе на сервере, который держит эту запись)?

*TTL (Time to Live) — это время, в течение которого DNS-запись может кэшироваться. Чтобы посмотреть TTL DNS-записи, можно использовать следующие методы:

## Команды

### Команда `dig`:
                    
`dig example.com`

                
В выводе будет указано значение TTL для каждой записи.

### Команда `nslookup`:

                    
`nslookup -type=any example.com`

                
В выводе также будет указано значение TTL.

### Команда `host`:

`host -a example.com`              
                
Эта команда также покажет TTL для записей.

На сервере: 
Если у вас есть доступ к DNS-серверу, вы можете просмотреть конфигурационные файлы, где указаны записи и их TTL.

## Утилиты
### nslookup: 

Это утилита для выполнения DNS-запросов. 
Она позволяет получать информацию о DNS-записях, таких как A, MX, SOA и другие. 
Пример использования:
                    
`nslookup example.com`

                
### host: 

Это простая утилита для выполнения DNS-запросов. 
Она используется для получения информации о доменных именах и IP-адресах. 
Пример использования:
                    
`host example.com`

                
### dig: 
Это мощная утилита для выполнения DNS-запросов, которая предоставляет более детальную информацию о DNS-записях и их параметрах. 
Пример использования:

`dig example.com`
                
Эти утилиты полезны для диагностики и анализа DNS-проблем.
